# 产品宪章

## 问题

桌面 Agent 可以观察并操作图形界面，手机用户却很难用自然语言完成跨 App 任务。手机端真正困难的部分不是生成文本，而是在受控权限下可靠看见界面、执行动作、验证结果，并正确处理歧义和敏感操作。

## 目标用户

Personal Jarvis 1.0 只服务项目作者本人，运行在一台经过专门配置的 Android 手机上。首要设备是小米/Redmi、Android 11+、HyperOS。该手机用于 Agent、自动化和测试，不承担重要主账号的日常使用。大众应用商店用户、iOS 用户和企业管理员不在范围内。

## 产品承诺

- 用户说清目标后，助手连续完成整个任务，而不是每一步都要求确认。
- 普通私聊消息在目标唯一时可直接发送。
- 账号登录、支付、验证码、密码、生物识别和安全页面必须停止并交还用户。
- 任务失败时说明走到哪一步、看到什么风险、用户可以如何接管。

## 产品原则

1. **执行优先**：用户意图明确时直接完成任务，避免多余弹窗。
2. **安全而不是隐私优先**：Developer Edition 可以保留完整个人上下文，但仍必须防止错误收件人、误付款、凭据泄漏和不可逆错误。
3. **观察优先于猜测**：UI 树、系统状态和结果验证优先，视觉模型只处理必要场景。
4. **本地守门**：模型可以提出动作，手机端的策略层拥有最终否决权。
5. **可替换模型**：规划、视觉定位、语音能力通过稳定供应商接口接入，不绑定单一模型。
6. **可接手**：任何任务都能暂停、取消和人工继续。
7. **文档先于扩展**：新模型、新 App、新权限必须有规格、测试和变更记录。

## Personal Jarvis 1.0 成功标准

- 用户能通过唤醒词、语音或文字启动任务并看到实时状态。
- 能可靠打开配置过的 App，并完成系统媒体控制。
- 能完成微信当前会话和指定联系人的普通回复并自动发送。
- 能在网易云音乐搜索并播放歌曲。
- 能读取通知、剪贴板、日历和截图建立连续上下文。
- 能完成至少一组跨 App 信息传递任务。
- 能在需要账号、支付或验证码时停止，并在本人完成后继续。
- Shizuku 不可用时，安全降级到无障碍能力或明确阻止任务。
- 所有账号、支付、验证码和不可逆安全操作均有可验证的人工接管点。
- 新模型开发者可仅依赖仓库文档完成 adapter、契约测试和评测接入。
