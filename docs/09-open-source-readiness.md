# 开源准备

> Status: Draft
> Owner: Maintainers
> Last reviewed: 2026-10-23

## 当前结论

小猪搭手未来可能开源，但目前尚未选择许可证，也没有公开维护者、治理方式和安全联系方式。项目内部正式成立，不等于可以公开发布；在这些事项完成前，仓库不得作为正式开源项目发布。

## 发布前必须决定

1. 许可证：Apache-2.0、AGPL-3.0 或自定义/双许可需要维护者结合商业化、网络服务和专利条款选择。
2. 贡献模式：DCO 或 CLA。
3. 治理：个人维护、核心维护者或委员会；谁拥有架构、风险策略和发布权。
4. 安全披露：启用 GitHub Private Vulnerability Reporting，指定响应负责人和时限。
5. 品牌与包名：项目名、图标、域名和应用包名。
6. 支持范围：只支持固定设备，还是接受社区兼容性贡献。

这些是需要维护者拍板的事项，不由实现 Agent 自行选择。

## 技术发布检查

- [ ] 所有 API Key、Token、签名文件和个人配置已移除。
- [ ] 固定测试语料和截图不含真实联系人、聊天、手机号或订单。
- [ ] 示例模型配置使用 `.env.example`，不包含真实供应商账户信息。
- [ ] README 的安装、构建、测试和已知限制与当前代码一致。
- [ ] 依赖许可证与目标许可证兼容。
- [ ] 依赖锁定并完成漏洞扫描。
- [ ] Android 权限、Shizuku 风险和数据流向有明确说明。
- [ ] 风险策略与支付/验证码边界在 README 和产品文档中一致。
- [ ] CI 在干净环境可重复运行。
- [ ] `AGENTS.md`、ADR、HANDOFF 和贡献指南已更新。

## 社区文档最低集合

- `README.md`
- `CONTRIBUTING.md`
- `SECURITY.md`
- `CODE_OF_CONDUCT.md`
- `LICENSE`
- Issue 和 PR 模板
- 架构、模型接入、App 技能和安全文档

## 发布策略

- 首个公开版本使用明确版本号和 Changelog。
- 发布 APK 与 GitHub Release 使用可验证的签名和校验值。
- 不把个人测试账号、内网地址或开发服务器密钥带入发布包。
- 公开后模型 adapter 采用独立目录和所有者，新增供应商不得修改通用 Agent 协议。
