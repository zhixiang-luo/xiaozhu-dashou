# 小猪搭手角色、唤醒与声音设计

> Status: Draft
> Owner: Product + Design
> Last reviewed: 2026-10-23

## 1. 设计决定

2026-10-23，维护者确认采用“暖科技任务猪”作为角色方向。

产品名保持“小猪搭手”，用户称呼和角色人格名为“猪哥”。角色与同级的“声账”小猪共享粉红猪鼻、圆耳朵、温和表情和印章式构图，但不直接复用声账的记账视觉。

角色不是贴在界面上的吉祥物，而是悬浮在 Android 系统层中的个人任务指挥官。设计目标是让用户在 32dp 到 64dp 的尺寸下仍能认出它，同时通过外观和状态表达“听见了”“正在理解”“正在操作手机”和“需要你接管”。

## 2. 形象系统

### 2.1 固定识别特征

- 粉红猪鼻和两侧圆耳，保留与声账的角色血缘。
- 奶油白脸部、深墨色手绘轮廓，避免玻璃拟态和金属机器人外壳。
- 头部外围的“任务轨道”：左侧暗示声音输入，右侧用三段刻度暗示任务执行。
- 猪鼻承担状态核心，聆听和执行时由它附近的光点或短波形提供反馈。
- 默认表情机敏、克制、可信，不持续卖萌。

### 2.2 科技感来源

科技感来自三件事：

1. 任务轨道和分段状态，而不是满屏电路纹理。
2. 只在活跃状态点亮的薄荷绿信号光，而不是紫蓝霓虹渐变。
3. 快速、明确、可中断的状态动效，而不是循环装饰动画。

### 2.3 禁止方向

- 不做 3D 盲盒手办、贴纸角色或儿童教育 App 风格。
- 不使用机器人头盔遮住小猪轮廓，否则与声账的角色联系会断裂。
- 不使用写实猪、肌肉拟人或夸张面部表情。
- 不使用持续旋转、持续呼吸或随机漂浮，避免悬浮球在界面上抢夺注意力。
- 不在图标中放中文短句、任务气泡或细小电路纹理。

## 3. 色彩与材质

| Token | 色值 | 用途 |
| --- | --- | --- |
| Canvas | `#F7F2E8` | 页面与概念稿底色，延续声账的暖纸感 |
| Bone | `#FFF9EF` | 小猪脸部、浅色表面 |
| Ink | `#20262B` | 轮廓、正文、深色背景 |
| Blush | `#E89A96` | 品牌主色、猪耳和猪鼻 |
| Blush Deep | `#A75258` | 粉色表面的可读文字与细节 |
| Signal | `#64DDC3` | 仅用于活跃状态的轨道和反馈光 |
| Signal Deep | `#0B695D` | 浅色背景上的可读强调色 |
| Amber | `#E9A94F` | 等待用户选择或接管 |

## 5. 悬浮球与状态

现有 Android 悬浮球为 64dp 圆形，长按后展开成“正在听…”胶囊。视觉升级保持这个交互骨架，不额外发明一个需要学习的新入口。

| 状态 | 视觉 | 动效与反馈 | 用户文案 |
| --- | --- | --- | --- |
| 待命 | 小猪半闭眼，轨道静止，粉色为主 | 不循环动，保持稳定 | 无 |
| 已唤醒 | 眼睛睁开，轨道亮绿一次 | 180ms 放大到 1.06 倍后回落，短触感 | 可选“在。” |
| 聆听 | 胶囊展开，声波从猪鼻左侧出现 | 声波随音量变化，不做随机跳动 | “正在听…” |
| 理解任务 | 轨道分为三段并依次点亮 | 单次 240ms 扫过，禁止无限旋转 | “我来看看。” |
| 执行任务 | 当前步骤对应的刻度常亮 | 新步骤出现时推进一格 | 显示具体动作 |
| 等待接管 | 整体转为琥珀色，角色视线向上 | 停在原位，不继续播放执行动画 | “这一步你来。” |
| 完成 | 轨道闭合一次，猪哥眨眼 | 420ms 后回到待命 | “弄好了。” |
| 失败 | 轨道在下方留出缺口 | 单次短促下沉，不摇头 | 说明失败步骤 |

所有状态必须同时提供颜色以外的线索，包括形状、动作、图标或文字。用户开启“减少动态效果”时，动画改为静态状态切换。

悬浮球展开宽度继续使用 164dp 左右；小屏设备至少保留 12dp 屏幕边缘安全距离。拖动后吸附左右任一侧，不自动漫游。系统安全页、支付页和用户明确暂停时，不显示诱导执行的动效。

## 6. “猪哥猪哥”唤醒

### 6.1 默认流程

1. 用户说“猪哥猪哥”。
2. 本地唤醒检测确认后，悬浮球睁眼，播放一次短促提示音并提供触感。
3. 用户可直接说“打开网易云音乐”，无需再次称呼；也可以在第一次呼叫时直接说完整任务。
4. 系统去掉句首的“猪哥，帮我”等角色前缀，只将实际目标交给任务规划。
5. 唤醒后 6 秒内没有有效语音，则静默回到待命，不弹“没有听清”。

“猪哥猪哥”包含连续重复音节，必须由本地唤醒模型和连续音频窗口共同判定。仅使用字符串匹配会把普通聊天中的“猪哥”误判为唤醒。

### 6.2 反馈优先级

- 普通亮屏场景：视觉状态和短提示音，不播报“我在”。
- 锁屏、耳机或用户看不到屏幕：播报短促、低音的“在。”。
- 系统静音：只使用触感和悬浮状态。
- 当前正在 TTS 播报：先停止播报，再进入聆听；用户说话优先。

### 6.3 隐私边界

- 本地唤醒检测前不向云端发送音频。
- 未唤醒的候选音频只保留滚动窗口，成功唤醒后只提交本次任务语音。
- 屏幕和其他 App 内容不能改变唤醒开关、免打扰设置或人工处理策略。

### 6.4 验收目标

- 100 条真实“猪哥猪哥”录音中，安静环境误拒绝不超过 5 条。
- 连续 60 分钟家庭、办公室和街边背景音中，每小时误唤醒不超过 1 次。
- 从唤醒完成到界面显示“正在听”的 P95 延迟不超过 350ms。
- 用户说“取消”或按下停止后，不再提交新任务动作。

这些是设计目标，不代表当前已经实现或验证。

## 7. 声音人格

### 7.1 推荐方向

采用“接地气的靠谱搭档”，不以强方言腔或全电子音制造角色感。

- 音色：28–35 岁男性，中低音，自然、温暖、略带笑意。
- 口腔状态：清晰但不过分咬字，避免客服播报腔。
- 节奏：短句、直接，必要时停半拍，不拖长语气词。
- 科技感：来自快速响应、准确复述和可预期状态，不来自金属混响。
- 情绪：遇到成功保持克制，遇到风险立即去掉笑意并放慢半拍。

“接地气”应体现在说法上，例如“行，我来”“弄好了”，而不是模仿某一地区的刻板口音。

### 7.2 统一话术

| 场景 | 推荐 | 避免 |
| --- | --- | --- |
| 唤醒 | “在。” | “主人，我在，请吩咐。” |
| 接受任务 | “行，我来。” | “好的呀，马上为您处理哦。” |
| 执行进度 | “正在打开微信。” | “请稍等，猪哥正在努力。” |
| 完成 | “弄好了。” | “任务已圆满完成，还有什么可以帮您？” |
| 需要选择 | “有两个张三，你要找哪个？” | “检测到多义实体，请确认候选对象。” |
| 人工接管 | “到付款页了，这一步你来。” | “风险等级过高，操作已阻断。” |
| 失败 | “卡在搜索页了，没有找到这首歌。” | “抱歉，系统开小差了。” |

### 7.3 仍需试听决定

正式接入 TTS 前制作三种候选声线，使用同一组 12 条任务话术盲测：

1. 自然中低音男声，推荐默认。
2. 更冷静、轻微科技质感的男声，供高级设置选择。
3. 清晰自然的年轻女声，验证不同用户偏好。

盲测关注可信度、自然度、长期使用是否厌烦、风险提示是否足够严肃、连续唤醒是否清晰。未完成试听前，不把任何供应商声线写死为正式角色。

## 8. 当前状态与下一步

已确定品牌方向并建立可视化资产，但当前 Android App 尚未接入新图标、常驻唤醒词、角色动画或正式 TTS。

下一步最小实现：

1. 将 App 图标和 Android 自适应图标接入工程。
2. 把现有悬浮球文字壳替换为猪哥待命、聆听、执行和接管四个基础状态。
3. 建立本地唤醒词接口和误唤醒测试，不直接依赖关键词字符串。
4. 用 12 条统一话术完成 TTS 声线试听，再决定默认声音和供应商。
