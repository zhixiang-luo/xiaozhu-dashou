# 猪哥角色 IP 圣经（v0.1）

> Status: Draft
> Owner: Product + Design
> Last reviewed: 2026-10-23

## 1. 品牌架构

“猪哥”是跨产品复用的角色 IP，“小猪搭手”是该角色当前服务的第一款产品。两者不能混为同一个名称：

- 用户称呼与角色名：**猪哥**。
- 当前手机 Agent 产品：**小猪搭手**。
- 品牌主张：**说一句，帮你做。**

系列产品采用“一个母版角色 + 产品主题套件”。后续产品只通过服装、道具、局部强调色和场景表达差异，不重新设计一只不同的猪。

头部标记适合 App 图标和系统悬浮球；完整全身角色用于启动页、引导、任务状态、宣传内容和 3D 资产。二者是同一角色的不同裁切，不是两个角色。

## 2. 角色设定

### 2.1 性格

猪哥是一位可靠、机敏、略带幽默的个人任务搭档。

- 先行动，再用短句说明结果。
- 遇到风险时立即收住轻松语气，明确指出需要本人处理的步骤。
- 不谄媚、不说教、不卖萌、不假装拥有未实现的能力。
- 对用户保持尊重，不称“主人”，不使用“亲”或客服式套话。
- 可以偶尔得意，但不能在错误联系人、支付或凭据场景表现轻松。

### 2.2 身体比例

V0.1 采用约 **3.2 头身（含耳）** 的行动型比例，比传统婴儿化吉祥物更成熟。

- 头部是识别主体，约占全身可见高度的三分之一。
- 躯干为柔和的豆形，肩窄、腹部略圆，避免肌肉化。
- 手臂和腿短而结实，保证动作轮廓清楚。
- 四指卡通手，指节简化但不做成圆球。
- 猪鼻始终位于面部横向中心；眼睛间距不得压缩。
- 尾巴末端的小信号灯是角色识别点，不做普通卷尾。

比例仍是 V0.1 评审项。若整体显得过于成人化，可整体调整到约 2.8 头身，但不得只缩短腿或放大头，避免侧面和 3D 模型失真。

### 2.3 固定造型

- 奶油白短款任务马甲或连体工装。
- 深墨色工具腰带，薄荷绿中央任务扣。
- 胸前一个薄荷绿任务节点；不堆叠真实按钮和屏幕。
- 粉色猪耳、侧脸和手部；深墨色线条负责稳定轮廓。
- 短尾末端的薄荷绿信号灯。
- 鞋底使用深墨色，保证小尺寸下全身仍有落地感。

当前不使用机器人装甲、头盔、透明面罩或外露机械关节。科技感来自工具、状态灯和任务轨道。

## 3. 产品变体规则

### 3.1 可以改变

- 产品专属围裙、马甲外搭或轻量配饰。
- 手持道具，例如账本、耳机、地图夹板、乐器或文件夹。
- 不超过 20% 面积的辅助色，用于产品识别。
- 场景、海报构图、字体和辅助图形。
- 任务状态下的局部动作与特效。

### 3.2 不可改变

- 头型、耳朵轮廓、猪鼻比例和眼睛间距。
- 奶油白脸部与粉色皮肤关系。
- 整体头身比例和核心轮廓。
- 默认性格、说话方式和安全边界。
- 尾巴末端信号灯的结构。
- 把角色改名成另一个动物，或改成无猪鼻的机器人。

产品变体应让熟悉猪哥的人一眼认出“它换了工作服”，而不是误认为系列中的另一个角色。

## 4. 资产层级

| 层级 | 资产 | 当前状态 |

| L0 品牌标记 | 头部主标记、App 图标、自适应/单色图标、横向组合 | V0.1 完成 |

## 5. 3D 生产前置条件

在 2D 四视图、手部结构和服装层次通过评审之前，不开始正式建模。正式 3D 母版必须包含：

- Blender 可编辑母文件。
- 正面、侧面、背面和四分之三渲染校准图。
- 身体骨骼、耳朵、尾巴、四指手和面部表情绑定。
- 待命、听见、执行、完成、等待接管和错误六组标准动作。
- PBR 材质、4K 以内贴图与移动端材质降级方案。
- 至少四级 LOD；移动端和 Web 运行时优先使用 GLB。
- 需要 Apple 场景时额外导出 USDZ。
- 游戏或传统引擎需要时额外导出 FBX。
- 透明背景角色渲染、方形社交媒体裁切和横版宣传构图。

3D 不是在生成图片上套骨骼。旧版图片只能作为轮廓参考，最终拓扑、UV 和关节位置必须服务于动画与运行性能。

## 6. 文件与版本规范

- 角色母版版本使用 `v0.1`、`v0.2`，禁止用 `final`、`new` 或日期代替语义版本。
- 矢量源文件、导出图和说明文档必须同时提交。
- App 运行时只引用导出资产，不直接依赖 Figma、个人云盘或生成图片缓存。
- 产品变体命名为 `variant-<product>-v<number>`。
- 同一版本的头部、全身和动作必须引用同一颜色令牌。
- 重大比例调整提升次版本号，例如从 `v0.1` 到 `v0.2`；只修复线条路径可保留补丁版本。

## 7. 原创与产权清单

维护者声明猪哥角色为原创设计。仓库当前只记录这一声明，不代表已完成商标检索或法律确权。

发布产品前应完成：

- 保存草图、矢量源文件、修改记录和提交时间，形成连续创作证据。
- 外部设计师、建模师和动画师签署著作权归属或完整授权协议。
- 记录生成式工具的使用范围、日期、提示词和人工修改过程，并确认商业使用条款。
- 对“小猪搭手”“猪哥”和主标记进行商标近似检索。
- 根据实际业务确认软件、通信、广告和 SaaS 相关商标类别。
- 为核心全身角色、四视图和代表性姿态办理著作权登记。
- 确定开源代码许可证与品牌授权边界；代码开源不自动授权商标和角色 IP。
- 在实体手办或周边商业化前，再评估外观设计专利和生产授权。

以上是资产治理建议，不构成法律意见。正式申请应由商标或知识产权专业人士复核。

## 8. V0.1 评审项

1. 约 3.2 头身是否足够亲近，还是应调整到约 2.8 头身。
2. 任务马甲的奶油白比例是否合适，是否需要露出更多粉色手臂。
3. 四指手的长度和关节是否适合后续建模与握持动作。
4. 尾巴信号灯是否足够独特，同时不显得像真实电线。
5. “换装不换脸”的系列策略是否适合第一个产品以外的方向。

V0.1 完成的是可编辑概念母版，不是最终量产资产。只有完成上述评审后，才进入标准姿态、动效和 3D 建模。

## 9. 设计工具试稿与首版采用

2026-10-23 使用 Figma Agent 基于文字描述生成过一版完整品牌板。该版本重新发明了角色轮廓和身体比例，与声账小猪及猪哥 V0.1 的身份连续性不一致，已被维护者拒绝。

这次失败确认了一条硬规则：**Figma、图像生成和其他设计工具可以用既有母版进行排版、精修和派生，但不能在缺少原图锁定的情况下重新设计猪哥。**

被拒绝的对照图保存在 `design/ip/v0.2/rejected/`，仅用于避免重复同样错误，不参与产品、宣传、动画或 3D 生产。

随后仅上传声账原始标记、猪哥头部标记和 V0.1 全身正面三张参考图，在 Figma 中使用原图手工重排了一版 `v0.2` 精修候选。候选保持角色原貌，只调整画板结构、标题层级、图标展示、规则说明和色板。由于 Figma Agent 当日额度耗尽，候选没有经过生成式重绘。导出见 `design/ip/v0.2/exports/identity-locked-refined.png`。

Figma 版本随后因整体表现仍未达到预期而停止使用。`v0.3` 改为在本地高保真 UI 原型中直接复用 V0.1 全身、头部图标和八种表情，以真实产品语境展示猪哥，不再让设计工具重新生成角色。源文件为 `design/ip/v0.3/preview.html`，主视觉导出为 `design/ip/v0.3/exports/hero-board-v2.png`。

2026-10-23，维护者确认暂时采用 V0.3 作为首个产品视觉方向。该版本用于 README 主视觉和 Android 启动图标，后续正式 3D 建模仍以 V0.1 母版为准。
