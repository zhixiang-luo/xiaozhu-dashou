# 手机本地背景记忆设计

> 状态：已确认
> 日期：2026-10-23

## 目标

在每次 DeepSeek 意图规划前提供相关背景，使“刚才那个会”“朱哥的年会”等省略表达能够
基于真实任务、日历和联系人上下文解析。

第一版采用结构化记忆与近期事件，不引入向量数据库。

## 记忆层次

- 工作背景：当前时间、时区、前台 App、页面标题。
- 未来日历：实时读取未来 14 天的可见系统日历事件。
- 近期任务：本地 SQLite 保存最近 24 小时任务摘要。
- 相关事件：最近 7 天的消息摘要、承诺和重要页面摘要。
- 联系人别名：别名到规范联系人名称。
- 用户偏好：可扩展的键值偏好。

## 数据流

```text
语音文字
  -> ContextBuilder
      -> CalendarContract 未来 14 天
      -> MemoryStore 最近任务/联系人/偏好
      -> 当前前台 App
  -> 紧凑 TaskContext
  -> /v1/tasks
  -> DeepSeek Intent
```

## 数据约束

- 不把密码、验证码、支付凭据或安全页内容写入 MemoryStore。
- 单次上下文最多 20 个日历事件、20 条近期任务、10 条相关记忆。
- 日历缓存不能替代操作前实时查询；修改和删除必须回查系统日历。
- 任务摘要只保存用户目标、动作类型和结果摘要。
- 记忆记录必须带时间、来源和类型。

## Android 存储

SQLite 数据库 `xiaozhu-memory.db`：

- `memory_events`：任务、承诺、消息摘要和页面摘要。
- `contact_aliases`：联系人别名。
- `preferences`：用户偏好。

## 服务端

- `/v1/tasks` 接受可选 `context`。
- 契约校验上下文结构，限制数组长度和文本长度。
- DeepSeek Prompt 包含紧凑 JSON 背景。
- 服务端不持久化该上下文；当前仍以手机为事实来源。

## 验收

- 创建日历事件后，下一次询问“那个会”时请求中包含该事件。
- 最近执行过的任务出现在 `/v1/tasks` 的 context 中。
- DeepSeek Prompt 能看到当前时间、时区、日历和近期任务。
- 手机重启后最近任务和偏好仍存在。
- 日历权限缺失时其他上下文仍可工作。
