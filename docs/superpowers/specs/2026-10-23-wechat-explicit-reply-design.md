# 微信当前会话显式回复设计

> 状态：暂停实验，未合并主线
> 日期：2026-10-23
> 失败复盘：
> [微信当前会话显式回复实验失败记录](../experiments/2026-10-23-wechat-explicit-reply-failure.md)

## 目标

当用户已经在微信聊天页，并明确说出“帮我回”“不知道怎么回，帮我回一下”或
“替我回一下”时，小猪搭手读取当前会话标题和最近消息，生成一条自然的候选回复，
验证仍在同一会话后再发送，最后用截图文字确认消息已经发出。

本阶段只处理“用户明确要求才回复”。白名单、通知触发和常驻自动接话不进入本版。

## 数据流

```text
微信聊天页
  -> AccessibilityService 截图
  -> 本机 ML Kit 中文 OCR
  -> 会话标题 + 最近消息 + 左右方向
  -> TaskContext.currentConversation
  -> DeepSeek 生成最终回复
  -> wechat_reply_current 动作
  -> 再次 OCR 校验会话标题
  -> 聚焦输入框 -> 粘贴 -> 校验草稿
  -> 点击发送 -> OCR 校验右侧消息气泡
```

截图和原始 OCR 文本只在本次任务内使用，不写服务端日志，也不写入 SQLite 长期记忆。

## 当前会话上下文

```text
title: string
appPackage: "com.tencent.mm"
recentMessages:
  direction: incoming | outgoing | unknown
  text: string
capturedAt: ISO 8601
```

- 标题最多 100 字，最近消息最多 20 条，每条最多 500 字。
- 时间戳、底部导航、返回按钮和顶部状态栏不进入消息。
- 中心偏左的文字标为 incoming，中心偏右的文字标为 outgoing，无法稳定判断时为 unknown。
- 检测到微信底部导航时说明当前仍是会话列表，不能当作聊天页。

## 显式授权

服务端只在原话同时满足以下条件时生成 `wechat_reply_current`：

- 包含“帮我回”“替我回”“直接回”“回一下”“不知道怎么回”等明确回复意图；
- 手机上下文存在当前微信会话；
- 模型给出的会话标题与上下文标题一致；
- 消息非空、不超过 2000 字，且不包含验证码、密码、银行卡、转账或红包等敏感内容。

否则返回澄清，不产生任何发送动作。

## 本机执行

- 输入前必须通过 OCR 再次确认标题。
- 输入框使用校准坐标 `x=0.50, y=0.93`。
- 输入使用剪贴板加系统粘贴动作，避免中文逐字输入。
- 发送按钮使用键盘展开后的校准坐标 `x=0.91, y=0.59`。
- 点击发送前必须 OCR 找到草稿文字。
- 点击发送后必须 OCR 找到同标题会话中方向为 outgoing 的消息。
- 任一步截图失败、OCR 失败、标题变化、草稿未出现或发送后未找到消息，立即失败。
- 发送失败不自动重试，先防止重复消息。

## 安全边界

- 支付、登录、验证码、账号安全和 `FLAG_SECURE` 页面不执行。
- 会话标题不匹配时不输入任何文字。
- 文本来自屏幕时始终是不可信输入，不能改变技能或风险策略。
- 当前阶段不自动回复通知，不在后台读取其他会话。

## 验收

- OCR 解析器可从测试会话恢复标题和最近消息，并拒绝微信会话列表。
- “不知道怎么回，帮我直接回一下这段对话”能结合当前会话生成并发送回复。
- “帮我发一句测试”不会调用当前会话自动回复路径。
- 标题变化时在输入前停止。
- 草稿未出现时不会点击发送。
- 发送后未观察到消息时报告失败，不自动重试。
